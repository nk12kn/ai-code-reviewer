About AI Code Reviewer & Security Auditor

AI Code Reviewer & Security Auditor is an educational developer utility and static application security testing (SAST) platform. Built to assist software developers, security students, and engineering teams, the application combines deterministic Abstract Syntax Tree (AST) inspection with an offline security rules engine to surface insecure code patterns before code reaches production repositories.

Project Objective

Modern application vulnerabilities frequently originate from basic coding flaws that are fully preventable: unsanitized query parameters, raw string formatting in database calls, unescaped user inputs passed to system shells, and unencrypted credentials committed to source trees. While complex vulnerabilities require deep threat modeling, a vast portion of software risk can be caught in the developer's immediate feedback loop.

Our objective is twofold:

1. Rapid In-Memory Auditing

Deliver immediate, offline-capable code audits without requiring heavyweight tool installations, project setup, or remote database synchronization.

2. Actionable Security Education

Equip developers with clear, educational explanations of why a pattern is hazardous, mapping findings directly to MITRE CWE and OWASP standards with working secure alternatives.

Architectural Pipeline

The application operates on a layered analysis pipeline that separates lexical parsing, security rule heuristics, scoring computation, and safe patch synthesis:

1 Language Detection & AST Parsing

Incoming source code is ingested in-memory by the FastAPI application. If the language is set to "Auto Detect", the backend inspects syntax markers, keywords, and file extension clues to resolve the target language (Python, JavaScript, TypeScript, Java, C/C++, or HTML). For Python, the system constructs a native Abstract Syntax Tree using Python's standard ast module, allowing the scanner to inspect call expressions, function definitions, and imported symbols deterministically.

2 Security Rules Engine & CWE Mapping

The code is evaluated against a curated catalog of security rules implemented in core/security_rules.py. Rules target specific anti-patterns such as SQL string concatenation (CWE-89), command execution via shells (CWE-78), hardcoded API tokens and private keys (CWE-798), weak hashing algorithms like MD5/SHA-1 (CWE-327), and unvalidated DOM sinks (CWE-79).

3 Deductive Scoring Algorithm

Unlike vanity metrics that grant arbitrary scores, our scoring engine begins at a baseline of 100 points and applies mathematically defined deductions weighted by vulnerability severity: Critical (-25 to -35 points), High (-15 points), Medium (-8 points), and Low/Info (-3 points). The final score is bounded between 0 and 100, mapping to grades A+ (90-100), A (80-89), B (70-79), C (60-69), and F (<60). Prior to executing an audit, the interface indicates "Not analyzed yet" to avoid misleading users.

4 Remediation Synthesizer & Unified Diff

When vulnerabilities are isolated, the rule engine applies deterministic transformations (such as substituting string concatenations with query parameters or replacing insecure imports). The engine uses Python's standard difflib module to compute a unified diff, rendering green additions and red deletions that can be reviewed visually or copied directly into source control.

5 Optional Semantic LLM Integration

For developers desiring deeper semantic context, the platform allows optional configuration of external LLM endpoints (such as Google Gemini or OpenAI). When configured, the user's API key is stored strictly within the client's local browser storage (localStorage) and used solely to query the designated API endpoint for supplementary remediation explanations.

Scope & Operating Boundaries

We believe in full transparency regarding what automated code analysis can and cannot accomplish. Static AST analysis inspects source code at rest. It is exceptionally effective at catching syntax-level blunders, insecure library calls, and hardcoded patterns. However, it cannot verify complex business logic flaws (such as multi-step workflow authorization), inspect live network firewalls, or substitute for comprehensive manual penetration testing. For full details on operating boundaries, review our Security Disclaimer.
