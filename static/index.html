Technical Architecture

How Static AST & AI Security Analysis Works

Understanding the multi-tier audit pipeline: lexical tokenization, syntax tree traversal, and heuristic classification.

1. AST Syntax Parsing

Rather than relying solely on brittle regex matching, the engine parses source code into an in-memory Abstract Syntax Tree. This allows the scanner to inspect call expressions, function parameters, and variable assignments deterministically without executing untrusted code.

  • Scope and call-graph inspection
  • Grammar validation per language
  • Context-aware string evaluation

2. OWASP & CWE Heuristics

Nodes are cross-checked against our curated rules engine mapped directly to MITRE CWE IDs and the OWASP Top 10. The engine classifies severity (Critical, High, Medium, Low, Info) based on real-world exploitability and calculates deductive health scores.

  • Deterministic offline detection
  • High-entropy secret scanning
  • Insecure library & API deprecations

3. Automated Patch Synthesis

Isolating vulnerabilities is only the first step. Our remediation synthesizer inspects flawed constructs and drafts secure drop-in replacements, delivering a standard Git-compatible unified diff ready for 1-click application in the editor.

  • Parameterized query conversions
  • Environment variable abstractions
  • Color-coded visual diff preview

Concrete Case Study

Example Analysis: Insecure vs. Remediated Code

An in-depth walkthrough of how our AST engine flags a high-severity SQL injection and transforms it into a hardened, parameterized database call.

Insecure Implementation CWE-89 Detected 
# FLAW: Direct string interpolation into SQL query
import sqlite3

def fetch_user_profile(user_id):
    conn = sqlite3.connect("app.db")
    cursor = conn.cursor()
    query = f"SELECT * FROM users WHERE id = '{user_id}'"
    cursor.execute(query)
    # Exploit payload: ' OR '1'='1
    return cursor.fetchone()
Remediated Secure Code Auto-Synthesized Patch 
# SECURE: Query placeholder with isolated parameter tuple
import sqlite3

def fetch_user_profile(user_id):
    conn = sqlite3.connect("app.db")
    cursor = conn.cursor()
    query = "SELECT * FROM users WHERE id = ?"
    cursor.execute(query, (user_id,))
    # Database engine treats payload strictly as literal data
    return cursor.fetchone()
Analysis Breakdown: In the vulnerable code, Python evaluates the f-string at runtime before the database engine sees it. If an attacker submits ' OR '1'='1, the SQL AST syntax tree is modified to return all records. In the remediated code, the query template is compiled first by the database engine, and the (user_id,) tuple is passed over the wire as isolated value data.

Limitations & Operational Boundaries of Automated Code Security Analysis

While static analysis (SAST) and AI-assisted audits provide an essential early-warning mechanism during development, engineering teams must maintain realistic expectations regarding their theoretical boundaries:

Business Logic Flaws
Automated tools evaluate syntax, library invocations, and known exploit signatures. They cannot infer human business rules, such as verifying whether user A is authorized to approve user B's financial transaction.
Dynamic Runtime Context
Static analysis inspects code at rest. Dynamic runtime conditions, distributed container networks, cloud IAM policies, and live database configurations must be validated via DAST and penetration testing.
Defense in Depth
Automated auditing is one layer of defense. Resilient software security requires threat modeling, architectural reviews, senior peer reviews, and routine third-party vulnerability assessments.

Frequently Asked Questions

Detailed answers on data processing, detection rules, scoring algorithms, and privacy.

How is my source code processed and is it saved on your servers?

When you submit a snippet or file, it is processed in server RAM by the FastAPI application solely for the duration of the scan. We do not persist submitted code to any database or disk storage. Once the audit response is generated, the in-memory representation is discarded. Standard web hosting access logs record HTTP request metadata (timestamp, IP, endpoint path, status code), but do not record submitted source code bodies.

How does the Security Health Score calculation work?

Prior to executing a scan, the score is uncalculated and displays "Not analyzed yet" with a score of "--". Once scanned, the score starts from a baseline of 100 points and applies mathematically defined deductions weighted by vulnerability severity: Critical issues (-25 to -35 points), High (-15 points), Medium (-8 points), and Low/Info (-3 points). Final scores map to grades A+ (90-100), A (80-89), B (70-79), C (60-69), and F (<60).

What is the difference between Offline Mode and External AI Mode?

By default, the scanner runs in 100% offline mode using our built-in Python AST parser and static heuristic rules without contacting any third party. If you choose to enable external AI (e.g. Google Gemini or OpenAI), your API key is stored strictly within your browser's local storage (localStorage) and used solely to query the designated API endpoint for supplemental natural-language remediation guidance.

Which programming languages are supported?

The engine provides dedicated AST and static rules for Python, JavaScript (ES6+), TypeScript, Java, C/C++, and HTML. When optional LLM analysis is active, semantic evaluation extends across additional languages including Go, Rust, PHP, and Ruby.

Can this tool detect business logic flaws or authorization bypasses?

No automated static scanner can fully deduce human business domain intent (e.g. whether a user should be allowed to view an invoice belonging to a different customer ID). While the tool flags known anti-patterns like unparameterized queries and hardcoded secrets, business logic flaws require threat modeling, human code review, and manual penetration testing.

How does the automated 1-click remediation feature work?

When vulnerabilities are identified, the rule synthesizer generates safe idiomatic replacements (such as binding query parameters or replacing insecure imports). The backend uses Python's difflib module to produce a unified diff. Clicking "Apply Fixes" immediately injects the remediated code into the editor so you can review or re-scan.

Can this tool replace formal penetration testing or compliance audits?

No. This utility is designed as an agile, developer-first inner-loop tool and educational knowledge base to catch mistakes during local development. It is not a replacement for formal security certifications, dynamic penetration testing, or human security code reviews.
